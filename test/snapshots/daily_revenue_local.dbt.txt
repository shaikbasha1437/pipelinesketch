# daily_revenue_local (dbt project)

Daily revenue rollup in DuckDB

Generated by [PipelineSketch](https://shaikbasha1437.github.io/pipelinesketch/). Requires dbt-core 1.10 or newer and dbt-duckdb.

```bash
pip install "dbt-core>=1.10" dbt-duckdb
cp profiles.example.yml ~/.dbt/profiles.yml   # then fill in the env vars
dbt parse
dbt build
```

- Raw tables in `raw` are landed by the orchestrator (Airflow, Dagster or Prefect exports) and declared as sources.
- Transform models build in the target schema (`staging`); warehouse-table sinks build as table or incremental models in their own schema.
- Column checks are generic `data_tests`; row-count, freshness, multi-column unique and custom checks are singular tests in `tests/`.
- Sinks outside the warehouse (files, lakes, Kafka) are documented as exposures.

# ===== models/staging/daily_revenue.sql =====
select
    order_date,
    count(*) as orders,
    sum(amount) as revenue
from {{ ref('orders_by_day') }}
group by order_date

# ===== models/staging/orders_by_day.sql =====
select
    order_id,
    amount,
    cast(created_at as date) as order_date
from {{ ref('paid_orders') }}

# ===== models/staging/paid_orders.sql =====
select *
from {{ source('raw', 'orders') }}
where status = 'paid'

# ===== models/staging/schema.yml =====
version: 2

models:
  - name: paid_orders
    description: "where status = 'paid'"
    columns:
      - name: order_id
      - name: customer_id
      - name: amount
      - name: status
      - name: created_at
  - name: orders_by_day
    description: 3 columns
    columns:
      - name: order_id
      - name: amount
      - name: order_date
  - name: daily_revenue
    description: group by order_date
    columns:
      - name: order_date
      - name: orders
      - name: revenue

# ===== tests/revenue_has_rows.sql =====
-- daily_revenue row count must satisfy: count(*) >= 1
select count(*) as row_count
from {{ ref('daily_revenue') }}
having not (count(*) >= 1)
